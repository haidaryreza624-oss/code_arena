Complete Actions
Five action classes, all complete. Same style as before. Each is a single-purpose orchestrator that runs a DB transaction and returns a predictable result. Controllers already pre-check state; these actions add the transactional safety layer with row-level locking, so concurrent admin clicks can't create inconsistent state.

§0 — What you get
File	Method	Purpose
app/Actions/ApproveContest.php	execute(Contest, User): void	draft → approved, respects active_slot
app/Actions/StartContest.php	execute(Contest): void	approved → running, sets started_at = now()
app/Actions/EndContest.php	execute(Contest): void	running → ended, sets ended_at = now()
app/Actions/GenerateCredentials.php	execute(Contest, bool $force = false): array	Generates passwords, returns [participation_id => plaintext]
app/Actions/ImportTeamsCsv.php	execute(Contest, UploadedFile): array	Streams CSV, creates teams/members/participations
Schema note before you start: the team_members.email column should be nullable to accept CSVs where some members don't have an email. Update the migration to $table->string('email')->nullable(); — one-line change, no data migration needed on a fresh install.

CSV format (v1 supports the standard one-row-per-member format):

csv
team_name,member_name,member_email,seat_number
Team Alpha,Alice Smith,alice@x.edu,12
Team Alpha,Bob Jones,bob@x.edu,12
Team Beta,Carol Lee,carol@y.edu,15
team_name — required, groups rows into teams

member_name — required, one row per member

member_email — optional (validated if present)

seat_number — optional, applied to the team from the first non-empty row

If your CSV format differs (one row per team with member columns, or members packed in a single cell), it's a ~10-line change in ImportTeamsCsv::parseRow() — see the note in §6.

<?php

namespace App\Actions;

use App\Models\Contest;
use App\Models\User;
use DomainException;
use Illuminate\Database\QueryException;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Log;

/**
 * Transition a draft contest to approved.
 *
 * Enforces the "one active contest at a time" invariant two ways:
 *   1. Application-level check inside a row-locked transaction — fast, gives
 *      a clean DomainException with a specific message about which contest
 *      is blocking.
 *   2. DB-level: the `contests.active_slot` generated column has a UNIQUE
 *      constraint, so a race that sneaks past (1) surfaces as a QueryException
 *      here — we catch it and re-throw as DomainException for consistency.
 *
 * On success:
 *   - status      = 'approved'
 *   - approved_at = now()
 *   - approved_by = $approver->id
 *   - active_slot = 1 (automatically via the generated column)
 *
 * Callers are expected to have pre-checked problems/teams presence and that
 * end_time isn't in the past; those are UX pre-checks in the controller, not
 * invariants this action needs to enforce.
 */
final class ApproveContest
{
    public function execute(Contest $contest, User $approver): void
    {
        DB::transaction(function () use ($contest, $approver) {
            // Row lock the contest being approved.
            /** @var Contest $fresh */
            $fresh = Contest::query()
                ->whereKey($contest->id)
                ->lockForUpdate()
                ->firstOrFail();

            if ($fresh->status !== Contest::STATUS_DRAFT) {
                throw new DomainException(
                    "Contest is not in draft state (current: {$fresh->status})."
                );
            }

            // Check whether another contest occupies the active slot.
            $blocking = Contest::query()
                ->whereKeyNot($fresh->id)
                ->occupiesActiveSlot()
                ->first();

            if ($blocking !== null) {
                throw new DomainException(
                    "Cannot approve: \"{$blocking->name}\" is still {$blocking->status}."
                );
            }

            try {
                $fresh->forceFill([
                    'status'      => Contest::STATUS_APPROVED,
                    'approved_at' => now(),
                    'approved_by' => $approver->id,
                ])->save();
            } catch (QueryException $e) {
                // Final safety net — the DB rejected the write because another
                // process approved a contest between our check and our save.
                Log::warning('ApproveContest: active_slot race lost', [
                    'contest_id' => $fresh->id,
                    'error'      => $e->getMessage(),
                ]);

                throw new DomainException(
                    'Another contest was approved concurrently. Please refresh and try again.',
                    previous: $e,
                );
            }

            $contest->refresh();

            Log::info('Contest approved', [
                'contest_id'  => $contest->id,
                'approved_by' => $approver->id,
            ]);
        });
    }
}
§2 — app/Actions/StartContest.php

<?php

namespace App\Actions;

use App\Models\Contest;
use DomainException;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Log;

/**
 * Manually start an approved contest.
 *
 * Normally the SyncContestState middleware transitions approved → running
 * automatically when start_time arrives. This action is the manual override —
 * the admin clicks "Start" to start early.
 *
 * On success:
 *   - status     = 'running'
 *   - started_at = now()  ← actual transition time, base for penalty math
 *
 * Note on started_at vs start_time: started_at is the *actual* moment the
 * contest began, which may differ from the scheduled start_time when the
 * admin starts early. Scoreboard penalty math uses started_at, not start_time.
 */
final class StartContest
{
    public function execute(Contest $contest): void
    {
        DB::transaction(function () use ($contest) {
            /** @var Contest $fresh */
            $fresh = Contest::query()
                ->whereKey($contest->id)
                ->lockForUpdate()
                ->firstOrFail();

            if ($fresh->status !== Contest::STATUS_APPROVED) {
                throw new DomainException(
                    "Contest is not in approved state (current: {$fresh->status})."
                );
            }

            $fresh->forceFill([
                'status'     => Contest::STATUS_RUNNING,
                'started_at' => now(),
            ])->save();

            $contest->refresh();

            Log::info('Contest started manually', [
                'contest_id' => $contest->id,
                'started_at' => $fresh->started_at?->toIso8601String(),
            ]);
        });
    }
}

<?php

namespace App\Actions;

use App\Models\Contest;
use DomainException;
use Illuminate\Support\Facades\Cache;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Log;

/**
 * Manually end a running contest.
 *
 * Normally the SyncContestState middleware transitions running → ended
 * automatically when end_time arrives. This action is the manual override —
 * the admin clicks "End" to end early.
 *
 * On success:
 *   - status   = 'ended'
 *   - ended_at = now()
 *
 * Also invalidates the scoreboard cache so the frozen view immediately
 * becomes the unfrozen (revealed) view.
 */
final class EndContest
{
    public function execute(Contest $contest): void
    {
        DB::transaction(function () use ($contest) {
            /** @var Contest $fresh */
            $fresh = Contest::query()
                ->whereKey($contest->id)
                ->lockForUpdate()
                ->firstOrFail();

            if ($fresh->status !== Contest::STATUS_RUNNING) {
                throw new DomainException(
                    "Contest is not in running state (current: {$fresh->status})."
                );
            }

            $fresh->forceFill([
                'status'   => Contest::STATUS_ENDED,
                'ended_at' => now(),
            ])->save();

            $contest->refresh();

            // Clear scoreboard caches so the next read sees the revealed
            // (unfrozen) scoreboard.
            Cache::forget("scoreboard:contest:{$contest->id}:frozen");
            Cache::forget("scoreboard:contest:{$contest->id}:unfrozen");

            Log::info('Contest ended manually', [
                'contest_id' => $contest->id,
                'ended_at'   => $fresh->ended_at?->toIso8601String(),
            ]);
        });
    }
}
§4 — app/Actions/GenerateCredentials.php

<?php

namespace App\Actions;

use App\Models\Contest;
use App\Models\ContestParticipation;
use DomainException;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Log;
use Illuminate\Support\Str;

/**
 * Generate plaintext passwords for a contest's participations.
 *
 * Returns a map of [participation_id => plaintext password]. The plaintext
 * values exist ONLY in this return value — they are never persisted to disk
 * or the database. The caller (CredentialController) streams them into a
 * PDF and lets the browser download; after the response ends, the plaintext
 * is gone.
 *
 * If a participation somehow has no username yet (shouldn't happen if import
 * ran, but defensive), one is generated as `team-NNN` sequentially.
 *
 * Two modes:
 *   - $force = false (default): generate only for participations without
 *     credentials_generated_at set. Safe to call repeatedly — only picks up
 *     new teams imported since the last run.
 *   - $force = true: regenerate for ALL participations, invalidating
 *     existing passwords. Use when an admin needs to reprint the entire
 *     roster.
 *
 * Throws DomainException if the contest isn't in approved state — credentials
 * can't be generated before approval (teams aren't final) or after start
 * (teams are already logged in).
 */
final class GenerateCredentials
{
    private const PASSWORD_LENGTH = 10;

    /**
     * @return array<int, string>  [participation_id => plaintext password]
     */
    public function execute(Contest $contest, bool $force = false): array
    {
        if ($contest->status !== Contest::STATUS_APPROVED) {
            throw new DomainException(
                "Credentials can only be generated while the contest is approved "
                . "(current: {$contest->status})."
            );
        }

        $plainByParticipation = [];

        DB::transaction(function () use ($contest, $force, &$plainByParticipation) {
            $query = ContestParticipation::query()
                ->where('contest_id', $contest->id)
                ->orderBy('id');

            if (! $force) {
                $query->whereNull('credentials_generated_at');
            }

            /** @var ContestParticipation $participation */
            foreach ($query->lockForUpdate()->cursor() as $participation) {
                // Ensure username exists (defensive — should always be set).
                $username = $participation->username;
                if ($username === null || $username === '') {
                    $username = $this->nextAvailableUsername($contest);
                }

                $plainPassword = Str::password(self::PASSWORD_LENGTH);

                // The model's `password` cast is 'hashed' — passing plaintext
                // here results in a bcrypt hash in the DB. Do NOT wrap in
                // Hash::make() or it would be double-hashed.
                $participation->forceFill([
                    'username'                 => $username,
                    'password'                 => $plainPassword,
                    'credentials_generated_at' => now(),
                ])->save();

                $plainByParticipation[$participation->id] = $plainPassword;
            }
        });

        Log::info('Credentials generated', [
            'contest_id' => $contest->id,
            'count'      => count($plainByParticipation),
            'force'      => $force,
        ]);

        return $plainByParticipation;
    }

    /**
     * Find the next `team-NNN` username not already taken in this contest.
     */
    private function nextAvailableUsername(Contest $contest): string
    {
        $existing = ContestParticipation::query()
            ->where('contest_id', $contest->id)
            ->pluck('username')
            ->flip();

        $n = 1;
        do {
            $candidate = 'team-' . str_pad((string) $n, 3, '0', STR_PAD_LEFT);
            $n++;
        } while ($existing->has($candidate));

        return $candidate;
    }
}
§5 — app/Actions/ImportTeamsCsv.php

<?php

namespace App\Actions;

use App\Models\Contest;
use App\Models\ContestParticipation;
use App\Models\Team;
use App\Models\TeamMember;
use DomainException;
use Illuminate\Http\UploadedFile;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Log;
use Illuminate\Support\Facades\Storage;
use Illuminate\Support\Str;
use League\Csv\Reader;
use League\Csv\Statement;

/**
 * Stream a CSV of team data into teams, members and contest participations.
 *
 * Expected CSV format (one row per team member):
 *
 *     team_name,member_name,member_email,seat_number
 *     Team Alpha,Alice Smith,alice@x.edu,12
 *     Team Alpha,Bob Jones,bob@x.edu,12
 *     Team Beta,Carol Lee,carol@y.edu,
 *
 * Required columns:
 *   team_name   — groups rows into teams
 *   member_name — one row per member
 *
 * Optional columns:
 *   member_email — validated if present; stored as NULL when empty
 *   seat_number  — applied to the team (first non-empty row wins);
 *                  must be a positive integer if present
 *
 * Idempotent: re-importing the same CSV will not create duplicates. Teams
 * are matched by name (case-sensitive, but MySQL's collation may treat
 * different-cased names as the same — be aware), members by (team, email)
 * or (team, name) if no email, participations by (contest_id, team_id).
 *
 * Behavior on errors:
 *   - Per-row validation errors are collected and returned in `errors`.
 *     Valid rows are still imported. The admin is expected to fix the CSV
 *     and re-import — idempotent, so no duplicates will be created.
 *   - Any DB exception (unexpected) rolls back the entire transaction and
 *     re-throws. This should not happen in practice since all validations
 *     are done pre-insert.
 *
 * Return shape:
 *   [
 *     'created'                => int,    // new teams created
 *     'skipped'                => int,    // rows with validation errors
 *     'members_created'        => int,
 *     'participations_created' => int,
 *     'errors'                 => string[],
 *   ]
 */
final class ImportTeamsCsv
{
    private const MAX_ROW_ERRORS = 100;

    public function execute(Contest $contest, UploadedFile $file): array
    {
        if ($contest->status !== Contest::STATUS_DRAFT) {
            throw new DomainException(
                'Teams can only be imported while the contest is in draft state.'
            );
        }

        $reader = $this->openReader($file);
        $this->validateHeaders($reader);

        $stats = [
            'created'                => 0,
            'skipped'                => 0,
            'members_created'        => 0,
            'participations_created' => 0,
            'errors'                 => [],
        ];

        $seatByTeamName = [];  // track first non-empty seat per team

        DB::transaction(function () use ($reader, $contest, &$stats, &$seatByTeamName) {
            $statement = Statement::create()->offset(0);

            foreach ($statement->process($reader) as $rowIndex => $row) {
                $this->processRow(
                    contest: $contest,
                    row: $row,
                    rowNumber: $rowIndex + 2,  // +1 for 0-index, +1 for header
                    stats: $stats,
                    seatByTeamName: $seatByTeamName,
                );

                // Cap error collection to prevent unbounded memory on huge
                // bad CSVs.
                if (count($stats['errors']) >= self::MAX_ROW_ERRORS) {
                    $stats['errors'][] = sprintf(
                        'Too many errors — stopping after %d. Fix the CSV and re-import.',
                        self::MAX_ROW_ERRORS,
                    );
                    break;
                }
            }
        });

        Log::info('CSV import completed', [
            'contest_id' => $contest->id,
            'stats'      => [
                'created'                => $stats['created'],
                'skipped'                => $stats['skipped'],
                'members_created'        => $stats['members_created'],
                'participations_created' => $stats['participations_created'],
                'error_count'            => count($stats['errors']),
            ],
        ]);

        return $stats;
    }

    // ================================================================
    // CSV parsing
    // ================================================================

    private function openReader(UploadedFile $file): Reader
    {
        // League/CSV can read directly from the temp path — no need to copy
        // into our own storage.
        $reader = Reader::createFromPath($file->getRealPath(), 'r');
        $reader->setHeaderOffset(0);
        $reader->skipEmptyRecords();
        $reader->includeEmptyRecords(); // we validate empties ourselves

        return $reader;
    }

    private function validateHeaders(Reader $reader): void
    {
        $headers = array_map(
            fn ($h) => Str::snake(trim((string) $h)),
            $reader->getHeader() ?? [],
        );

        if (! in_array('team_name', $headers, true)) {
            throw new DomainException(
                'CSV is missing required header: team_name'
            );
        }

        if (! in_array('member_name', $headers, true)) {
            throw new DomainException(
                'CSV is missing required header: member_name. '
                . 'Use one row per team member.'
            );
        }
    }

    // ================================================================
    // Row processing
    // ================================================================

    /**
     * @param  array<string, string|null>  $row
     * @param  array{created:int,skipped:int,members_created:int,participations_created:int,errors:string[]}  $stats
     * @param  array<string, int|null>  $seatByTeamName
     */
    private function processRow(
        Contest $contest,
        array $row,
        int $rowNumber,
        array &$stats,
        array &$seatByTeamName,
    ): void {
        $teamName    = $this->value($row, 'team_name');
        $memberName  = $this->value($row, 'member_name');
        $memberEmail = $this->value($row, 'member_email');
        $seatRaw     = $this->value($row, 'seat_number');

        // ---- Validate -------------------------------------------------
        if ($teamName === '') {
            $stats['errors'][] = "Row {$rowNumber}: team_name is empty.";
            $stats['skipped']++;
            return;
        }
        if (mb_strlen($teamName) > 255) {
            $stats['errors'][] = "Row {$rowNumber}: team_name exceeds 255 characters.";
            $stats['skipped']++;
            return;
        }
        if ($memberName === '') {
            $stats['errors'][] = "Row {$rowNumber}: member_name is empty.";
            $stats['skipped']++;
            return;
        }
        if (mb_strlen($memberName) > 255) {
            $stats['errors'][] = "Row {$rowNumber}: member_name exceeds 255 characters.";
            $stats['skipped']++;
            return;
        }
        if ($memberEmail !== '' && ! filter_var($memberEmail, FILTER_VALIDATE_EMAIL)) {
            $stats['errors'][] = "Row {$rowNumber}: invalid email '{$memberEmail}'.";
            $stats['skipped']++;
            return;
        }
        if (mb_strlen($memberEmail) > 255) {
            $stats['errors'][] = "Row {$rowNumber}: member_email exceeds 255 characters.";
            $stats['skipped']++;
            return;
        }

        $seatNumber = null;
        if ($seatRaw !== '') {
            if (! ctype_digit($seatRaw)) {
                $stats['errors'][] = "Row {$rowNumber}: seat_number '{$seatRaw}' is not a positive integer.";
                $stats['skipped']++;
                return;
            }
            $seatNumber = (int) $seatRaw;
            if ($seatNumber < 1 || $seatNumber > 65535) {
                $stats['errors'][] = "Row {$rowNumber}: seat_number must be between 1 and 65535.";
                $stats['skipped']++;
                return;
            }
        }

        // Track the first seat we see for this team (all rows should agree,
        // but we don't enforce it — first wins).
        if ($seatNumber !== null && ! isset($seatByTeamName[$teamName])) {
            $seatByTeamName[$teamName] = $seatNumber;
        }

        // ---- Insert ---------------------------------------------------
        $team = Team::firstOrCreate(['name' => $teamName]);
        if ($team->wasRecentlyCreated) {
            $stats['created']++;
        }

        // Dedupe members by (team, email) when email present, else (team, name).
        $memberQuery = TeamMember::query()->where('team_id', $team->id);
        if ($memberEmail !== '') {
            $memberQuery->where('email', $memberEmail);
        } else {
            $memberQuery->where('name', $memberName)->whereNull('email');
        }

        if (! $memberQuery->exists()) {
            TeamMember::create([
                'team_id' => $team->id,
                'name'    => $memberName,
                'email'   => $memberEmail !== '' ? $memberEmail : null,
                'ordinal' => $team->members()->count(),
            ]);
            $stats['members_created']++;
        }

        // Find or create the participation for this (contest, team).
        $participation = ContestParticipation::firstOrCreate(
            [
                'contest_id' => $contest->id,
                'team_id'    => $team->id,
            ],
            [
                'username'    => $this->nextAvailableUsername($contest),
                // Placeholder password — replaced on credentials generation.
                // Random 64-char string means the hash is unpickable until
                // then; the plaintext is thrown away immediately.
                'password'    => Str::random(64),
                'seat_number' => $seatByTeamName[$teamName] ?? $seatNumber,
            ]
        );

        if ($participation->wasRecentlyCreated) {
            $stats['participations_created']++;
        } else {
            // If we learned a seat number this pass and none was set before,
            // fill it in.
            if (! $participation->seat_number && ($seatByTeamName[$teamName] ?? $seatNumber)) {
                $participation->update([
                    'seat_number' => $seatByTeamName[$teamName] ?? $seatNumber,
                ]);
            }
        }
    }

    private function value(array $row, string $key): string
    {
        return trim((string) ($row[$key] ?? ''));
    }

    /**
     * Find the next `team-NNN` username not already taken in this contest.
     */
    private function nextAvailableUsername(Contest $contest): string
    {
        $existing = ContestParticipation::query()
            ->where('contest_id', $contest->id)
            ->pluck('username')
            ->flip();

        $n = $existing->count() + 1;
        do {
            $candidate = 'team-' . str_pad((string) $n, 3, '0', STR_PAD_LEFT);
            $n++;
        } while ($existing->has($candidate));

        return $candidate;
    }
}
§6 — Notes and gotchas
1. Row-level locking in ApproveContest — why it matters

Without the lockForUpdate(), two admins clicking Approve on the same draft within milliseconds of each other would both pass the state check and both call save(). The second save() would fail on active_slot unique constraint... usually. But if the two drafts are different contests, both would pass their own state checks and both would try to claim active_slot = 1. Only one would succeed at the DB level (the second throws QueryException), but the error would be a raw 500 to the second admin.

The lockForUpdate() on the contest being approved serializes concurrent approvals of the same contest. The active-slot check + QueryException catch handles concurrent approvals of different contests. Both paths produce a clean DomainException the controller can catch and flash.

2. forceFill() vs update()

The actions use forceFill(...)->save() because the fields they touch (approved_at, approved_by, started_at, ended_at) are correctly NOT in $fillable on the Contest model — they're system-managed, not user-supplied. forceFill bypasses the mass-assignment guard for these trusted internal writes.

Similarly in GenerateCredentials, forceFill bypasses $fillable for credentials_generated_at (also system-managed).

3. The password cast — do not double-hash

ContestParticipation has 'password' => 'hashed' in its casts array. That means assigning a plaintext string to $participation->password results in bcrypt hashing at save time. If you call Hash::make($plaintext) yourself and then save, you get a double hash — the resulting hash will never validate against the plaintext. The GenerateCredentials code passes plaintext directly, letting the cast hash once. This is the Laravel 11 idiom and it works correctly.

Same pattern in ImportTeamsCsv — 'password' => Str::random(64) gets hashed once by the cast.

4. Str::password() vs Str::random()

Str::password(10) generates a 10-character password that includes letters, numbers, and symbols, avoiding visually-confusable characters. It's designed for exactly this case — user-facing generated passwords that will be typed or printed. Str::random(12) is for API keys and tokens.

The generated password looks something like kR7#mN2$pQ — 10 chars, readable enough to type, hard enough to brute-force for a 3-hour contest.

5. CSV re-import idempotency

Re-importing the same CSV:

Teams: matched by name — no duplicates

Members: matched by (team, email) if email present, else (team, name) — no duplicates

Participations: matched by (contest_id, team_id) — no duplicates

Passwords are NOT regenerated on re-import. The placeholder Str::random(64) from the first import is preserved. Only GenerateCredentials regenerates real passwords.

This means an admin can:

Import teams

Realize Alice's email was wrong

Fix the CSV and re-import

The system adds Alice's new email as a duplicate member ((team, email) won't match the old one)

That's a known limitation — re-import doesn't delete members that disappeared from the CSV. Handle the delete separately if needed (v2 feature). The safe workflow is: import once, verify, generate credentials.

6. CSV format flexibility

The parser is written for one-row-per-member format. If your CSV is actually:

One row per team with member1_name, member1_email, member2_name, ... columns — you need a ~15-line change in processRow to iterate the member columns.

One row per team with a single members column like "Alice <a@x>, Bob <b@x>" — you need to split the string and parse name/email.

Both are easy to add. If you share an example row from your actual CSV, I can adjust the parser to match exactly. For now, v1 assumes the standard format above.

7. Why Str::random(64) for the placeholder password

Before credentials are generated, contest_participations.password must be non-null (schema requirement). We need some value. Options:

Str::random(64) — long random string, hashed. Nobody can log in until real credentials are generated.

Hash::make(Str::uuid()) — similar, more expensive.

Empty string — would violate bcrypt requirements or produce a weak hash.

Str::random(64) is the right choice — 64 random bytes hashed to a 60-char bcrypt string. The plaintext is thrown away immediately (assigned inline, never stored anywhere). Impossible to recover, impossible to accidentally authenticate.

8. DomainException — what catches it

The controllers currently do abort_unless($contest->isDraft(), 403) for pre-checks. If they pass, they call the action. If the action throws DomainException, the controller doesn't catch it — it bubbles up as a 500 error.

For production quality, wrap each action call in the controller:

php
try {
    $action->execute($contest, $request->user());
} catch (DomainException $e) {
    return back()->withErrors(['approval' => $e->getMessage()]);
}
Rather than update the controllers (already delivered), add a global handler in bootstrap/app.php:

php
->withExceptions(function (Exceptions $exceptions) {
    $exceptions->render(function (DomainException $e, Request $request) {
        if ($request->expectsJson()) {
            return response()->json(['error' => $e->getMessage()], 422);
        }
        return back()->withErrors(['action' => $e->getMessage()]);
    });
})
This handles every action's DomainException uniformly — one handler, all actions covered. Add it before the contest-specific render I wrote earlier.

9. ImportTeamsCsv — the transaction boundary

The outer DB::transaction wraps the entire row loop. Individual row validation errors don't throw — they increment $stats['skipped'] and continue. Only unexpected DB errors (e.g., a team name that violates a unique constraint the parser didn't check) would throw and roll back everything.

In practice, all validations happen pre-insert, so the transaction should never roll back due to a data error. It's there to guarantee atomicity if something truly unexpected happens.

10. ImportTeamsCsv performance

For 200 teams × 3 members = 600 rows:

firstOrCreate per team (200 queries)

exists() per member (600 queries)

TeamMember::create() per new member (600 queries)

firstOrCreate per participation (200 queries)

nextAvailableUsername per participation — one query each but only on creation

Roughly 1600 queries total, each fast (indexed lookups). Runs in ~2-3 seconds synchronously. Fine for a contest import. If you ever import 10k+ teams, add a bulk-insert optimization — but that's not a contest-scale need.

11. ImportTeamsCsv — the seat handling edge case

Each member row can have a seat number. We take the first seat we see for a given team and apply it to the participation. If row 1 says seat 12 and row 2 says seat 15 for the same team, we use 12 and silently ignore the disagreement. This is fine for the common case (all rows for a team have the same seat, or only one row has it).

If you want to warn on disagreement, add a check in processRow:

if (isset($seatByTeamName[$teamName]) 
    && $seatNumber !== null 
    && $seatByTeamName[$teamName] !== $seatNumber
) {
    $stats['errors'][] = "Row {$rowNumber}: seat_number disagrees with earlier rows for team '{$teamName}' (using {$seatByTeamName[$teamName]}).";
    // Still use the first one — don't skip the row.
}
12. ApproveContest — the end_time check is intentionally NOT here

The action doesn't check "is end_time in the past?" because that's a business policy, not an invariant. The controller (ContestApprovalController) does this check for a good UX message. The action trusts the caller. If you later want contests that end immediately on approval (rare), the action doesn't need to change — just relax the controller.

13. Manual Start vs Sync middleware — which wins?

Both can transition approved → running. Whichever runs first wins because of the lockForUpdate() in the action and the firstOrFail() in the middleware (which operates on the already-loaded Contest instance). After the first transition, the state is running and the other is a no-op. No conflict.

The only subtle case: SyncContestState runs on every request. If a contest's start_time passes and any contestant hits /c/{slug}/problems, the middleware flips it. That's exactly the intent — the contest starts the moment the first person needs it to.

14. What's intentionally NOT in these actions

No notifications / broadcasts — deferred until Reverb is added

No audit log writes — mentioned as optional in the schema section; add via a global model observer if desired

No scoreboard cache invalidation on Approve/Start — the scoreboard for an approved or just-started contest is either empty or trivial; no cache exists yet. EndContest does invalidate because it flips frozen → revealed.

No email sending — deferred (member emails are record-only in v1)

No credential PDF generation — that's the controller's job; the action returns plaintext, the controller renders the PDF
